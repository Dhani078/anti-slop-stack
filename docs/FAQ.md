# Frequently Asked Questions (FAQ)

### What defines AI code slop?
AI slop refers to low-effort boilerplate, hallucinated single-implementation abstractions, narrative comments, repetitive purple/indigo UI gradients, and generic corporate prose generated by large language models that degrade software maintainability.

### Why zero dependencies?
Build tools and quality gates must run instantly and never introduce security vulnerabilities through transitive dependencies. anti-slop-stack relies strictly on native Node.js APIs (`fs`, `path`, `child_process`).

### Does anti-slop-stack support languages other than JavaScript?
Yes. Layer 1 (Code Slop) audits TypeScript, JavaScript, Python, PHP, Go, and Rust. Layer 2 audits modular architectures across all text formats. Layer 3 audits CSS, Tailwind, Vue, JSX, and HTML. Layer 4 audits Markdown and documentation.

### Can I run this in pre-commit hooks without delaying git commit?
Yes. Running `anti-slop staged` evaluates only files staged in the index via `git diff --cached`, executing in under 20 milliseconds on typical feature commits.

### How does anti-slop-stack compare to ESLint or Biome?
ESLint and Biome focus primarily on syntax errors, AST correctness, and language-specific formatting. anti-slop-stack targets higher-level engineering degradation caused by AI generators: Hungarian interface inflation, narrative comment noise, generic AI UI templates, empty catch blocks, and marketing buzzwords. It complements existing linters.
